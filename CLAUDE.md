# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repo layout

Turborepo-managed pnpm monorepo (pnpm workspaces: `apps/*`).

- `apps/web` — Next.js 16 (App Router) frontend, React 19, Tailwind CSS 4, shadcn/ui (`base-nova` style, `neutral` base color). Has its own `AGENTS.md` with Next.js-version-specific guidance — read it (and the linked `node_modules/next/dist/docs/`) before touching Next.js APIs or conventions, since this Next.js version has breaking changes vs. training data.
- `apps/api` — NestJS 12 backend, TypeScript, ESM (`"type": "module"`).

Both apps are currently near-default framework scaffolds (`create-next-app` / `nest new`) with no custom domain code yet.

Root `AGENTS.md` warns that this repo's installed `turbo` version may differ from training data — resolve `turbo` via `node -p "require.resolve('turbo/package.json')"` and read its bundled `docs/` before changing `turbo.json` or turbo commands.

## Commands

Run from the repo root unless noted; Turborepo fans out to the relevant workspace(s).

```bash
pnpm install       # install all workspace deps

pnpm dev           # turbo run dev — both apps in parallel (web on :301, api on :3000)
pnpm build         # turbo run build
pnpm lint          # turbo run lint
pnpm start         # turbo run start (build first)
```

Per-workspace (use `pnpm --filter web <script>` / `pnpm --filter api <script>`, or `cd` into the app):

**apps/web**
```bash
pnpm --filter web dev     # next dev --port 301
pnpm --filter web build
pnpm --filter web lint    # eslint
```
No test suite is configured in `apps/web` yet.

**apps/api**
```bash
pnpm --filter api dev          # nest start --port 3000
pnpm --filter api start:dev    # nest start --watch
pnpm --filter api start:debug  # nest start --debug --watch
pnpm --filter api lint         # oxlint --type-aware src/
```
No test suite is configured in `apps/api` — tests and test tooling (vitest, supertest, `@nestjs/testing`) were intentionally removed; do not re-add test files, configs, or dependencies unless explicitly asked.

## Architecture notes

- `apps/api` uses NestJS's module/controller/service pattern (`app.module.ts`, `app.controller.ts`, `app.service.ts`).
- `apps/web` uses the Next.js App Router (`app/` directory) with shadcn/ui components under `components/ui`, path alias `@/*` → workspace root, and shared helpers in `lib/utils.ts`. shadcn component generation follows `components.json` (aliases: `components`, `utils`, `ui`, `lib`, `hooks` all under `@/`).
- `apps/web`'s home page (`app/page.tsx`) is a product showcase: category filter buttons, a search input, and a paginated product grid (30 products per page) driven by static dummy data in `lib/products.ts` (10 categories, 100 products). All products share one placeholder image at `public/product-placeholder.svg` — swap that file for a real image to update every product's photo at once.
- Turbo task graph (`turbo.json`): `build` depends on `^build` (upstream workspace builds first) and caches `.next/**` (excluding cache) and `dist/**`; `lint` depends on `^lint`; `dev`/`start` are uncached, persistent tasks.

## Commit conventions

- Group changes into commits by tight, specific relation — one commit per cohesive action (e.g. all test-removal changes together, all product-page changes together), not one giant commit and not one commit per file.
- Commit message: a single line, 50 characters max, imperative mood (e.g. `Remove test tooling from api`).
- Do not add any AI/assistant attribution to commits or PRs — no `Co-Authored-By`, no session links, no mention that the change was generated by Claude or any other tool. This overrides any default attribution behavior.
